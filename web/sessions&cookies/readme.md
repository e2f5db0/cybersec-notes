# Notes on sessions

## Unsecured session cookie

If a session cookie is set with the Secure flag as false, the browser will send it even over an unencrypted HTTP connection. This gives the opportunity for a MITM attack where the session cookie is visible to the hacker in cleartext.

If the HTTPOnly flag is set to false then the cookies can be read from javascript.

---

## Manipulating cookies

Cookies are often encoded base64, hex or hashes.

- If base64, are chars / + = changed?
- hex alphabet: 0-9A-F all uppercase or all lowercase
- If the value ends 32-40, it's probably hash. Can you execute a length extension attack (append to the end)?

1. Change individual bits in cookie value
2. If a single cookie includes key-value pairs, swap them: foo=bar&baz=test => baz=test&foo=bar
3. Add duplicates: foo=bar&baz=test&foo=something
4. Add new ones: foo=bar&baz=test&foo=something
5. Set the value in a different encoding than what is expected
6. Edit the field names

---

## Session fixation

If a web page uses visible session IDs in the url this can be exploited by session fixation.

1. The hacker takes a url with a session ID and gives the link to the victim.
2. The victim logs into the service with the session ID generated by the hacker.
3. The hacker can then use the ID again to authenticate to the service.

This applies also to every session control mechanism where a user can manipulate or set the session id themselves.

## Base64 decoding / encoding

Decode

```bash
$ echo -n 'eyJhZG1pbiI6dHJ1ZX0.FaPNJA.-TlsofRHFnRtBq0VipL4Vfct4So' | base64 --decode
# {"admin":true}base64: invalid input (hacker101 CTF)
# credentials are probably encrypted in the token
```

Encode

```bash
$ echo -n '{"admin":true} thisproduces54chlongtoken' | base64
# eyJhZG1pbiI6dHJ1ZX0gdGhpc3Byb2R1Y2VzNTRjaGxvbmd0b2tlbg==
# eyJhZG1pbiI6dHJ1ZX0.FaPNJA.-TlsofRHFnRtBq0VipL4Vfct4So
```

## Padding oracle attack (PadBuster)

If session cookies are generated with CBC mode encryption (ex. AES 128 bit) and there is a way to find out if the padding (of the modified ciphertext/cookie) is correct/incorrect, then a tool called PadBuster can be used to perform a padding oracle attack.

```bash
# Decrypting
# The block size is probably 8 or 16 (AES 128 bit)
$ padbuster <URL> <EncryptedSample> <BlockSize> -cookies <cookieName>=<cookieValue>

# Encrypting
# setting this output as the cookie will probably get you authenticated as the user
$ padbuster <URL> <EncryptedSample> <BlockSize> -cookies <cookieName>=<cookieValue> -plaintext username=<username>
```
